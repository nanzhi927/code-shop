# 企业管理系统-SpringBoot（毕设学习版）

基于 SpringBoot 的企业门户完整前后端系统**教学版**：一套代码同时包含**前台企业官网**（5 栏目）与**后台管理端**（9 组功能），数据库 44 张表导入即用，适合毕业设计、课程设计的学习参考与技术交流。

> 本仓库为教学版，供学习交流使用；完整版（含全部资料、真机演示视频、运行说明与答疑）获取方式见文末引导。

## 项目简介

- **前台**：标准企业官网，5 个栏目——首页、关于我们、产品展示、新闻中心、联系我们。所有栏目内容由后台配置，前台刷新即生效，无需修改代码。
- **后台**：完整管理端——权限管理（用户/角色/菜单/部门）、内容管理（文章/产品图片/轮播图）、文件管理、系统监控（在线用户/系统日志/运行监控）。
- **数据库**：MySQL，库名 `admin1`，44 张表（Activiti 工作流表 25 张 + 系统表 11 张 + 门户业务表等），脚本自带建表语句与示例数据，导入即用。
- **工程**：标准 Maven 结构，JDK 1.8，SpringBoot 2.0.3.RELEASE。

## 数据库设计

库名 `admin1`，共 44 张表，按前缀分三类：

| 分类 | 数量 | 说明 |
|---|---|---|
| `act_*` 工作流表 | 25 张 | Activiti 5.22 引擎标准表，部署时自动生成，无需手工设计 |
| `sys_*` 系统表 | 11 张 | 用户、角色、菜单、部门、日志等权限与系统管理表（经典 RBAC） |
| 门户业务表等 | 8 张左右 | 文章、产品、轮播图、文件等前台内容相关（表名清单【待核实】） |

脚本包含 DROP/CREATE 语句与示例数据，重复导入不冲突。ER 图建议按"权限层 / 内容层 / 流程层"三层绘制：权限层画用户-角色-菜单-部门 RBAC 关系（必画），内容层画文章/产品/轮播图与栏目的关系，流程层画 2-3 张工作流代表表即可。

## 快速开始

第 1 步：导入数据库

```sql
create database admin1 default character set utf8;
use admin1;
source 你的路径/admin1.sql;
```

或命令行直接导入：

```bash
mysql -u用户名 -p admin1 < admin1.sql
```

导入后应能看到 44 张表；表数量不足说明脚本未导完，重新导入即可。

第 2 步：修改配置。打开 `src/main/resources/application.yml`：
- 数据库连接：库名、用户名、密码改成你自己的；
- 端口：默认 80，被占用可修改 `server.port`（如 8080）；
- Redis：确认指向本机 6379。

第 3 步：启动

```bash
mvn spring-boot:run
```

或构建后运行 jar：

```bash
mvn clean package -DskipTests
java -jar target/bootdo-2.0.0.jar
```

第 4 步：访问验证
- 前台：`http://localhost/home`
- 后台登录：`http://localhost/login`（登录后进入 /index；账号信息见完整版运行说明）

看到启动完成日志即运行成功。

## 常见问题（FAQ）

**Q1：启动报数据库连接失败（Access denied / Communications link failure）？**
九成是 application.yml 里数据库密码/库名没改对，或 MySQL 服务未启动。先在命令行用同样账号密码登录 MySQL 验证。

**Q2：报端口被占用（Port 80 was already in use）？**
默认端口 80 容易被其他程序占用，把 `server.port` 改成 8080 等未占用端口，或关闭占用进程。

**Q3：Maven 依赖下载慢或工程报红？**
配置国内镜像源（如阿里云 Maven 镜像），删除本地仓库中下载不完整的目录后重新 update；IDEA 导入后等待依赖全部下载完成再看报错。

**Q4：为什么 44 张表里有 25 张 act_ 开头的表？**
那是 Activiti 工作流引擎的标准表，部署工作流模块时自动生成，不需要手工设计，论文中如实说明来源即可。

**Q5：Redis 是必须的吗？**
按工程配置需要 Redis（默认本机 6379），未启动会报连接错误。安装并启动本机 Redis 即可。

**Q6：前台内容在哪里改？**
全部在后台改：文章在"文章信息管理"，产品在"产品图片管理"，首页大图在"轮播图管理"，前台刷新即生效，无需改代码。

**Q7：这个项目能用作毕业设计吗？**
可以作学习参考。基于开源脚手架（bootdo）二次定制开发，建议在其上做自己的业务定制，答辩时如实说明，能讲清原理比"从零手写"的说法更稳。

**Q8：有论文或开题报告吗？**
没有，仓库只有源码与数据库脚本。论文请自己撰写，技术实现思路可以交流。

**Q9：支持哪些系统？MySQL 8 可以吗？**
Windows / MacOS 均可；MySQL 5.5 / 5.7 / 8.0 都支持。

**Q10：演示视频里端口是 18080，和文档说的 80 不一致？**
演示视频为录制时修改过的端口，项目默认端口为 80，以配置文件与运行说明为准。

## 学习与答辩参考

拿这套系统做毕设参考的同学，建议按这条线准备：

1. **先跑通再动笔**：环境搭好、系统跑起来，对照页面把功能清单过一遍，论文的"系统分析"章素材就有了；
2. **技术点吃透两个**：权限（Shiro 用户-角色-菜单，页面级+按钮级）和工作流（Activiti 引擎与 25 张标准表的来源），答辩被追问就围绕这两个展开；
3. **数据库那章如实写**：44 张表 = 工作流标准表 + RBAC 系统表 + 业务表，能说清构成本身就是加分项；
4. **演示提前彩排**：登录后台→改一篇文章→切前台刷新出现，这个联动操作现场演示效果很好；
5. **如实说明来源**：基于开源脚手架二次定制，能讲清每个模块的原理，比"从零手写"的说法更经得起追问。
