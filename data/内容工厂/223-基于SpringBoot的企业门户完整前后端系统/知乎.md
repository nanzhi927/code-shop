### 正文（1500-3000 字干货长文，9 段结构）

**一、背景：毕设真正的卡点不是代码**

先说结论：企业管理系统是 Java 毕设里难度适中、答辩友好度靠前的方向，适合大部分普通水平的同学。

自己做毕设、也陪身边同学踩过一圈坑，发现真正的卡点从来不是"不会写代码"，而是三件事：选题开题说不清系统长什么样、拿到工程跑不起来、答辩技术点讲不清。这篇拿一套我实测跑通的 SpringBoot 企业门户系统（前台官网+后台管理，44 张表），从选题到答辩完整过一遍，每一段都是可以直接对照论文目录用的干货。

**二、选题与选型：为什么这个方向适合毕设**

1. 业务零解释成本。前台就是企业官网（首页、关于我们、产品展示、新闻中心、联系我们），答辩页面一放，老师秒懂，不用花时间解释"这个系统是干嘛的"。
2. 技术点密度合适。典型的 SpringBoot + MyBatis + Shiro + Thymeleaf 架构，权限管理、内容管理、系统监控，每个模块都能在论文里独立成节。
3. 工作量扎实但不失控。数据库 40+ 张表，ER 图和表结构设计那章素材管够；同时业务逻辑不深，不会把自己绕进去。
4. 风险提示（诚实说）：如果连 MySQL 安装都费劲，先补环境再谈选题；拿到任何工程务必先跑通再写论文，别论文写完发现环境起不来。

**三、系统功能设计：模块怎么划分**

这套系统一句话：**前台企业官网 + 后台管理系统，同一个 SpringBoot 工程完成**。这个划分天然对应论文三章结构：前台展示层（界面设计章）、后台业务层（功能实现章）、权限与安全（系统安全设计章）。

前台 5 栏目：首页（轮播大图+栏目入口）、关于我们、产品展示（列表+详情）、新闻中心（列表+详情）、联系我们。

后台按功能分 9 组：①用户/角色/菜单/部门管理；②在线用户/系统日志/运行监控；③文章信息管理；④产品图片管理；⑤首页轮播图与轮播图类型管理；⑥文件管理（图片附件统一管理）。

**加分点在联动**：后台"文章信息管理"是前台"新闻中心"的数据源，"产品图片管理"对应前台"产品展示"，"轮播图管理"控制首页大图——后台改内容，前台刷新即生效，不改代码。论文里把这条数据流画成图，就是"系统总体设计"章的核心插图，也回答了老师爱问的"后台改了前台哪里变"。

**四、数据库设计：44 张表怎么分类**

库名 admin1，脚本共 44 张表，新手一看会慌，拆开很清晰：

- `act_*` 工作流表 25 张：Activiti 5.22 引擎自带，部署时自动生成，**不需要你手工设计**；
- `sys_*` 系统表 11 张：用户、角色、菜单、部门、日志等权限与系统管理表，经典 RBAC 设计；
- 门户业务表与其他辅助表：文章、产品、轮播图等前台内容相关（按扫描记录约各 4 张，表名清单【待核实】）。

这给数据库设计章的启发是：**成熟系统的表 = 框架表 + 系统表 + 少量业务表**，你真正要设计的是业务那几张。论文里如实写"系统采用 Activiti 工作流引擎，引入其标准表结构 25 张；系统权限表沿用经典 RBAC 设计 11 张；业务表围绕门户内容设计"——专业又诚实，答辩被追问也扛得住。

ER 图建议画三层：权限层（用户-角色-菜单-部门的 RBAC 关系图，必画）、内容层（文章/产品/轮播图与栏目）、流程层（工作流核心表关系示意，画 2-3 张代表表即可，别硬画 25 张）。

**五、技术实现要点：两个值钱的技术点讲透**

**1. Shiro 权限（RBAC）**。结构一句话：用户挂角色，角色挂菜单，菜单挂权限标识，权限标识控制到按钮——同样是"用户管理"页，管理员能看见删除按钮，普通角色看不见。登录后 Shiro 完成两件事：认证（账号密码对不对）和授权（能看到哪些菜单、能点哪些按钮）。辅助功能：在线用户、系统日志（操作留痕，安全审计）、运行监控。答辩被问"为什么不自己写过滤器"，答：Shiro 提供现成的会话管理、缓存集成和注解式鉴权，自己写容易漏安全边界——选型理由比功能本身更能体现工程素养。

**2. Activiti 5.22 工作流**。一句话：把"审批/流转"这种多步骤流程从代码里抽出来交给引擎管。这套系统内置引擎和在线流程设计器：网页上拖拖拽拽画流程图（开始→审批节点→分支→结束），画完直接部署，改流程不用改代码，对应数据库里那 25 张 act_ 表。被问"工作流用在你项目哪里"，老实答集成为通用能力、审批类业务可基于它扩展，比硬编一个不存在的场景可信得多。

顺带两个小点：Thymeleaf（被问"为什么不做前后端分离"，答：内容展示型系统服务端渲染简单直接、利于收录、部署简单——技术选型服务于业务）；缓存 Ehcache + Redis（权限菜单这类高频数据走缓存，可作性能优化章节素材）。

**六、运行与部署：从导库到跑通**

环境：JDK 1.8+、Maven、MySQL 5.5/5.7/8.0、Redis（本机 6379），Windows/MacOS 均可。

步骤：
1. 建库导脚本：`create database admin1 default character set utf8;` → `use admin1;` → `source admin1.sql;`，导完应看到 44 张表，少表就是没导完；
2. 改 `src/main/resources/application.yml`：数据库用户名密码、端口（默认 80，被占用可改 8080）、Redis 地址；
3. 启动：`mvn spring-boot:run`，或 `mvn clean package -DskipTests` 后 `java -jar target/bootdo-2.0.0.jar`；
4. 验证：前台访问 /home，后台 /login 登录（管理员账号 admin，密码见运行说明）。

**七、踩坑与经验（真实高频问题）**

1. 数据库连接失败（Access denied / Communications link failure）：九成是配置文件里密码/库名没改对，或 MySQL 服务没启动。先用命令行 `mysql -u xxx -p` 验证账号能不能登。
2. 端口被占用（Port 80 was already in use）：80 端口容易被其他程序占用，把 server.port 改成 8080 即可，或找到占用进程处理。
3. Maven 依赖下载不动/工程报红：换国内镜像源，删掉本地仓库里下载一半的目录重新 update；IDEA 导入后等依赖全部下完再看报错。（细节因环境而异，报错信息可以贴在评论区一起看【待核实】）
4. 经验之谈：先跑通再动论文；演示提前彩排（登录→后台改一篇→前台刷新出现，这个联动操作是全场高光）。

**八、答辩要点：这套系统会被问什么**

- "权限怎么做的"——Shiro、RBAC、用户-角色-菜单、菜单树控页面级、权限标识控按钮级，一分钟讲完；
- "数据库多少张表"——44 张 = 25 工作流 + 11 系统 + 业务表，能说出构成就赢了大部分同学；
- "为什么选这个技术栈"——SpringBoot 自动装配省配置、MyBatis SQL 可控、Shiro 管 RBAC、Thymeleaf 服务端渲染简单直接，每个都有具体理由；
- "是你自己写的吗"——千万别说从零手写，被追问三行就露馅。诚实答"基于开源脚手架（bootdo）二次开发，我在其上做了业务功能的调整和调试验证，能讲清每个模块的原理"，反而过关；
- "出 bug 怎么排查"——答思路不答空话：看日志定位异常堆栈→分层排查（前端请求有没有发出、Controller 有没有进、SQL 对不对）→最小化复现修复。

**九、总结与引导**

企业管理系统方向：好开题、好写论文、好答辩，前提是把权限、表构成、前后台联动这三个技术点吃透。我这套实测跑通过，演示流程也录了完整视频；丑话说前面——**论文是没有的**，只有工程+数据库脚本+运行说明，论文要自己写；这套基于开源脚手架（bootdo）二次开发，供学习交流用。

模块划分、表结构、答辩思路有疑问的，评论区留言，看到会回。想讨论怎么把这个结构套到自己题目上的，评论区一起聊。
