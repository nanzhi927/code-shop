# 09-发布SOP（流程 / 时间 / 频率 / 自检）

## 一、一项目多平台发布顺序（固定流程）

```
① Gitee/GitHub 仓库先发（教学版）
      ↓ README/主页互相导流
② 自建站商品页（完整版承接页，演示视频放这里）
      ↓
③ 内容平台：小红书 → B站（演示视频）→ 抖音（视频切片）→ 知乎 → 微博
      ↓ 所有内容 CTA 终点指向自建站/主页
④ 闲鱼商品（低价引流款）最后上，承接搜索流量
```

> 原则：**先仓库 → 再内容平台 → 全部指向自建站**。内容平台发之前，自建站页面必须已就绪（否则流量落地为空）。

## 二、各平台发布流程与规范

| 平台 | 顺序 | 最佳时间 | 频率 | 封面/形式规范 | 注意事项 |
|---|---|---|---|---|---|
| 小红书 | 内容平台第 1 位 | 工作日 12:00-13:00 / 18:00-22:00 | 每周 3-5 篇，单项目 1-2 篇 | 3:4 竖图，首图大字（业务词+毕设），后图后台截图 | 正文零联系方式；不连续硬广（软硬穿插）；发布后 1 小时内回评 |
| B站 | 第 2 位 | 周末 10:00-12:00 / 20:00-22:00 | 每项目 1 个演示长视频 + 运行教程 | 封面：项目名+技术栈大字+截图 | 简介可放自建站链接；避免"代做"；视频加时间轴章节 |
| 抖音 | 第 3 位 | 12:00 / 18:00-21:00 | 每周 3-5 条（B站视频切片） | 竖屏，前 3 秒出系统画面 | 导流只说"主页/私信"；不连写"加微信" |
| 知乎 | 第 4 位 | 任意（长尾流量） | 每项目 1-2 个回答/文章 | 无封面要求，首段直接给结论 | 正文不放外链；用个人简介/置顶评论承接；写干货长文 |
| 微博 | 第 5 位 | 12:00 / 20:00-22:00 | 每周 2-3 条 | 九宫格截图/短视频 | 带 2-3 个话题；可与超话联动 |
| 闲鱼 | 最后 | 任意 | 商品长期挂，每周擦亮 2-3 次 | 首图后台截图拼图+大字 | 按虚拟商品类目；详情写明"仅含源码+数据库"；不写"永久/包更新" |
| Gitee/GitHub | 全流程第 1 位 | 任意 | 一次性发布 | README 规范（见各项目文件） | 全中文；开源协议声明"仅学习交流"；README 指向自建站 |

## 三、发布前违规自检动作（每篇必做）

1. 对照 **02-违禁词自查表** 过一遍 30 秒流程。
2. 检查标题：主关键词是否前置、是否命中 03-关键词库 里的词。
3. 检查 CTA：是否指向"主页/私信/免费咨询"，而不是硬卖。
4. 检查事实：端口、账号、表数、技术栈版本与**项目事实卡**一致。
5. 检查脱敏：截图无学校名/姓名/学号，视频无敏感信息。

## 四、数据记录表模板（每周复盘一次）

| 日期 | 平台 | 项目 | 标题 | 曝光 | 阅读/播放 | 点赞 | 评论 | 私信 | 转化（进微信/下单） | 备注（哪条标题有效） |
|---|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | | |

**复盘动作**：
- 曝光高但互动低 → 换封面/首图大字
- 互动高但私信少 → 检查 CTA 是否太弱
- 某类标题命中搜索词带来稳定曝光 → 记录该标题结构，复用到下一项目
