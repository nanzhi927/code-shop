# 内容充分性标准（每篇必须写足）

> 问题：一篇文章内容太薄（小红书正文仅 400 字、闲鱼描述笼统、知乎没有干货），发出去没说服力、也吃不到搜索流量。
> 原则：**一个项目 = 每个平台一篇文章，但每篇必须"写满写厚"**——信息密度够、要素齐全、读的人能自己做决定。

---

## 一、各平台最小篇幅与必备要素

### 1. 小红书（正文 800-1200 字）
必须包含（缺一不可）：
1. 痛点开场（1-2 句，扎心场景）
2. 项目背景与选题理由（为什么这个题目好做/好答辩）
3. **功能逐条列全**：前台每个栏目 1 句说明 + 后台每组功能 1 句说明（用 ✅ 分点）
4. 技术栈与版本（SpringBoot 2.0.3 / MyBatis / Shiro / Thymeleaf / Druid / Activiti / JDK1.8）
5. 数据库（表数量级 + 分类说明，如"44 张表：工作流 25 + 系统 11 + 业务 8"）
6. **包含材料清单**（源码 / 数据库脚本 / 运行说明 / 截图 / 演示视频；哪些没有要明说）
7. 运行环境与门槛（要装 JDK/MySQL/Redis、端口、导入脚本）
8. 适合人群（谁适合买：技术栈匹配的、时间紧的、答辩要讲技术点的）
9. 常见问题 2-3 个（能不能跑 / 有没有论文 / 能不能改 / 环境不会装怎么办）
10. 学习/答辩建议（怎么用这套准备答辩）
11. CTA（评论区/私信 + 定制需求评估）
12. 配图 6-9 张的建议（每张什么内容）

### 2. 闲鱼（描述 600-1000 字）
1. 关键词密集的标题（业务词+毕设源码+技术栈+可运行+含数据库）
2. 项目一句话定位
3. 功能逐条（前台/后台分开列）
4. 材料清单（含/不含写清楚）
5. 运行环境要求
6. 交付方式（网盘/在线发，多久发）
7. 服务说明（远程部署 +XX、一对一讲解 +XX、答疑范围）
8. 常见问题 3-5 个（含"能不能改功能""是不是残缺""能不能先看演示"）
9. 注意事项（虚拟商品规则、仅供学习参考、不代写论文）
10. 引导（先看演示视频再决定）

### 3. B站（简介 600-1000 字 + 口播脚本 800-1500 字/5-7 分钟）
简介必须含：项目介绍、完整功能清单、技术栈与版本、数据库说明、运行环境、时间轴（5-8 段）、适合人群、常见问题、获取与咨询方式、标签与分区。
口播脚本：分镜（画面）+ 口播词 + 时长，按 220-250 字/分钟。

### 4. 抖音（文案 60-120 字 × 3-5 条变体）
每条独立可用：钩子（前 3 秒）+ 卖点 2-3 个 + CTA；另给 3 个封面大字方案。

### 5. 微博（500-800 字长微博）
痛点 + 项目介绍 + 功能清单 + 材料 + 技术栈 + CTA + 话题 2-3 个 + 九宫格配图说明。

### 6. 知乎（1500-3000 字干货长文）
1. 问题背景（学生真实困境）
2. 选题与选型分析（为什么这个方向适合毕设）
3. 系统功能设计（模块划分 + 每个模块做什么）
4. 数据库设计（表分类、关键表字段举例、ER 思路）
5. 技术实现要点（权限/工作流/缓存等 2-3 个技术点讲透）
6. 运行与部署步骤（含常见报错）
7. 踩坑与经验（真实、具体）
8. 答辩要点（这套系统会被问什么）
9. 总结 + 合规引导（评论区/私信；不硬广）

### 7. Gitee / GitHub README（2000 字以上）
项目简介（含截图位）、演示与文件清单链接、功能清单（前台/后台）、技术栈表格、**目录结构树**、数据库设计（表分类 + 主要表说明）、环境要求、**快速开始（分步 + 命令）**、常见问题 FAQ（8-10 条）、注意事项、更新记录、Star/咨询引导。全中文。

### 8. 商品页详情（1200-2000 字）
卖点前置（3 条）、项目简介、功能模块分组逐条、技术架构与版本、数据库说明、运行环境、**交付清单（含/不含）**、FAQ（8-10 条）、购买与售后说明、注意事项（仅供学习参考）。

## 二、写作质量要求（避免"字数够但没用"）
1. **具体 > 形容词**：写"前台 5 栏目：首页/关于我们/产品展示/新闻中心/联系我们，内容全部后台配置"；不写"功能强大、应有尽有"
2. **主动交代缺点**：论文没有 / 需自己装环境 / 演示视频端口改过——反向提升可信度
3. **可执行**：命令、端口、路径、表名尽量给到（如 `mvn spring-boot:run`、`admin1.sql`、端口 80）
4. **分段清晰**：多用小标题与分点，手机端可读
5. **合规**：零违禁词（对照 00-通用素材/02）；正文不放联系方式/站外链接（放主页/私信）
6. **每篇都要有 CTA**：指向"主页/私信咨询 + 定制需求评估"

---

## 三、审核方式（机械可查）
产出后逐篇统计：正文实际字数 vs 最小字数、必备要素条数（缺项列出）、违禁词命中数。**字数不达标或要素缺失即打回重写。**
