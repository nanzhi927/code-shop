### 正文（1500-3000 字干货长文，9 段结构）

**一、背景：订单类题目真正的卡点**

先说结论：网上点餐系统是 Java 方向里**业务最直白、闭环最完整**的一类题目，难度适中，但也是"踩坑率"很高的一类——因为它有订单，订单有状态，状态一多就容易讲不清。

自己做项目、也陪同学改过几次开题，发现卡点从来不是"不会写代码"，而是三件事：说不清这个系统和现成外卖 App 的差别在哪、拿到工程跑不起来、答辩被问订单流转时只能干笑。这篇拿一套我实测跑通的 SpringBoot 点餐系统（用户 + 美食店 + 管理员三端，11 张表）从选题到答辩过一遍，每段都能直接对照论文目录用。

**二、选题与选型：为什么这个方向适合毕设**

1. **业务零解释成本**。点餐这件事人人有体感，前台页面一放，不用解释"这个系统干嘛的"。
2. **闭环完整、章节好分**。浏览美食 → 点餐生成订单 → 订单审核与支付状态 → 评价 → 收藏，这条链天然对应"系统分析 / 功能实现 / 系统测试"三章，每章都有实打实的内容。
3. **技术点密度合适**。SpringBoot + MyBatis-Plus + Shiro 权限，三端角色（用户 / 美食店 / 管理员）本身就是一个很值的权限设计题。
4. **诚实提醒**：如果你的题目还没定，先想清楚"三端角色要不要都做"——只做用户端会很薄，做齐三端工作量才撑得住；另外任何一套工程都要先跑通再动笔，别论文写完发现环境起不来。

**三、系统功能设计：三端怎么划分**

这套系统一句话：**一个 SpringBoot 工程，三种角色各自的工作台**。这个划分对应论文里的"角色与权限设计"章。

前台 6 栏目：首页（轮播图，后台可配）、美食店、美食信息、美食评价、美食资讯、个人中心。其中美食信息支持点餐与收藏，个人中心里包含个人信息、美食订单管理、美食评价管理、我的收藏管理。

用户角色：注册登录、维护个人资料（账号/姓名/性别/年龄/头像/手机/配送地址）、点餐提交订单、查看订单、写评价、管理收藏。

美食店角色：登录后维护本店美食信息（新增/修改/删除）、处理本店订单、查看与回复顾客评价、维护店铺资料（名称/照片/电话/介绍/地址/招牌美食/联系人）。

管理员角色（后台）：用户管理、美食店管理、美食分类管理、美食信息管理、美食订单管理、美食评价管理、美食资讯、轮播图管理、个人中心。

**加分点在数据联动**：美食信息挂在美食分类和美食店下，订单引用美食信息，评价又作用在订单/美食上——后台改一条美食，前台列表和详情立刻变。论文里把这条数据流画成图，就是"系统总体设计"章的核心插图。

**四、数据库设计：11 张表怎么分类**

库名 `springboott01gx`，脚本共 **11 张表**，比动辄四五十张表的项目轻得多，但结构一点都不含糊：

- **系统类 3 张**：`users`（管理员）、`token`（登录令牌）、`config`（配置与首页轮播图）；
- **业务类 8 张**：`yonghu`（用户）、`meishidian`（美食店）、`meishifenlei`（美食分类）、`meishixinxi`（美食信息）、`meishidingdan`（美食订单）、`meishipingjia`（美食评价）、`news`（美食资讯）、`storeup`（收藏）。

**订单表是重点，值得单独讲**。它的字段设计把一笔生意的全过程都覆盖了：订单编号、美食名称、店铺账号与名称、联系电话、`jiage` 单价、`goumaishuliang` 点餐数量、`zongjiage` 总金额、用户账号/姓名/手机、配送地址、`xiadanshijian` 提交时间、`sfsh` 是否审核（默认"否"）、`shhf` 审核回复、`ispay` 是否支付（默认"未支付"）。

论文里这张表就是画状态图的依据：**待审核 → 已审核 / 已回复 → 已支付**，再叠加"订单是否属于当前登录用户/店铺"的过滤条件。ER 图建议画三层：

1. **角色层**：用户—订单、美食店—美食信息、管理员—系统配置的归属关系；
2. **业务层**：美食分类 → 美食信息 → 订单 → 评价的主链；
3. **辅助层**：收藏、资讯、配置三张独立小表。

**五、技术实现要点：三个值钱的技术点**

**1. Shiro 权限 + 三端角色隔离。** 工程用 Apache Shiro 1.3.2 做登录鉴权，配合一个令牌拦截器（`AuthorizationInterceptor`）在请求进入业务代码前校验身份。三端角色的本质是：**同一份数据，不同角色看到不同菜单、能操作不同范围**——用户只能看自己的订单，美食店只能管自己店的美食和订单，管理员看全量。答辩被问"权限怎么做的"，就答：登录签发令牌 → 请求携带令牌 → 拦截器校验 → 业务层按角色过滤数据范围。这比只答一句"用了 Shiro"扎实得多。

**2. 角色菜单与入口分流。** 前台点餐端和后台管理端是两套前端资源，落在同一个工程里：`front/` 是用户与商家看到的点餐端，`admin/dist/` 是管理员后台。两者共用同一套后端接口，靠角色区分入口。这个设计的好处是部署简单——一个 jar 起来，两个入口都能访问，答辩演示时切页面很有说服力。

**3. MyBatis-Plus 提升开发效率。** 依赖 `mybatis-plus` 2.3 + starter，单表增删改查基本不用手写 SQL，复杂查询再用 XML 映射（`resources/mapper/` 下按实体分文件，共 12 个映射文件）。被问"为什么用 MyBatis-Plus 而不是纯 MyBatis"，答：通用 CRUD 交给框架，业务 SQL 仍然可控，兼顾效率和可控性。

顺带两个小点：登录密码由 `MD5Util` 工具类处理（脚本示例数据里部分账号是明文，实际使用建议统一走加密）；工程还引入了百度 AI 的 `java-sdk` 4.4.1，`CommonController` 里有 `AipFace` 相关工具类，具体启用了哪些能力我没有逐项确认，答辩前务必自己点开确认，**没跑通的功能不要在论文里写**。

**六、运行与部署：从导库到跑通**

环境：JDK 1.8+、Maven、MySQL 5.7 / 8.0，Windows / macOS 均可。

步骤：

1. 导入数据库：`db.sql` 里自带建库语句（库名 `springboott01gx`），直接 `mysql -u root -p < db.sql`，或客户端里执行整份脚本；导完确认 **11 张表**都在；
2. 改配置：打开 `src/main/resources/application.yml`，把 `datasource` 的用户名/密码改成本机的，数据库地址默认 `127.0.0.1:3306`；时区参数是 `GMT%2B8`；
3. 启动：`mvn spring-boot:run`；或 `mvn clean package -DskipTests` 后 `java -jar target/springboott01gx-0.0.1-SNAPSHOT.jar`；
4. 访问：端口 **8080**，**路径必须带上下文** `springboott01gx`——前台 `/springboott01gx/front/index.html`，后台 `/springboott01gx/admin/dist/index.html`（管理员账号说明文档里有，`abo`）。

**七、踩坑与经验（真实高频问题）**

1. **页面 404 / 空白**：九成是漏了上下文路径，只访问 `localhost:8080` 是拿不到页面的，必须跟 `/springboott01gx/...`。
2. **登录失败或报数据库异常**：先查三件事——MySQL 服务起了没、yml 里的密码改没改、11 张表导全没导全；脚本重复执行前先看建库语句，避免往旧库上叠。
3. **端口 8080 被占**：这个端口太常见，被 IDEA 或其他服务占了就换一个（`server.port`），换完记得访问路径端口同步改。
4. **三端账号别混用**：用户、美食店在点餐端登录，管理员在后台页面登录，账号来源不同，混着试会一直提示密码错误。
5. **经验之谈**：先跑通再动笔；演示提前彩排"用户点餐 → 商家看到订单 → 处理 → 用户评价"这条链，比单点功能演示完整得多。

**八、答辩要点：这套系统会被问什么**

- "为什么做成三端？"——因为点餐业务天然有三个利益方：点的人、卖的人、管的人，一个角色一套数据范围，这样设计才闭环；
- "订单状态怎么流转？"——看 `sfsh` 是否审核与 `ispay` 是否支付两个字段，待审核 → 审核回复 → 支付完成；
- "权限怎么实现的？"——Shiro 登录鉴权 + 令牌拦截器 + 按角色过滤数据范围，用户只能看自己的订单；
- "数据库多少张表，怎么分的？"——11 张 = 系统类 3 + 业务类 8，把订单表字段讲清最加分；
- "是你自己写的吗？"——别硬说从零手写。如实说"基于现成脚手架做的业务调整与调试，订单、评价、三端权限这几块我能讲清实现过程"，反而经得起追问；
- "出 bug 怎么排查？"——看日志定位异常 → 分层排查（前端请求发没发、控制器进没进、SQL 对不对）→ 最小化复现修复。

**九、总结与引导**

点餐系统这个方向：好开题、章节好分、答辩有东西演示，前提是把**三端角色、订单状态、权限过滤**这三个点吃透。我这套实测跑通过；资料里带了一份论文初稿和答辩 PPT，但丑话说前面——**初稿格式和查重要自己重新过，不能直接交**；环境也要自己装（JDK / Maven / MySQL）。另外这套**没有演示视频**，随资料的是 10 张运行截图，介意的先看清楚。

三端结构、订单表设计、答辩思路有疑问的，评论区留言，看到会回。想讨论怎么把这个结构套到自己题目上的，评论区一起聊。
