### 正文（1500-3000 字干货长文，9 段结构）

**一、背景：车辆管理是交通类毕设里的"安全牌"**

先说结论：车辆管理系统难度适中、业务闭环清晰、答辩友好度靠前，适合大部分普通水平的 Java 方向同学。自己做项目、也陪身边同学踩过一圈坑，发现真正的卡点是三件事：选题开题说不清系统长什么样、拿到工程跑不起来、答辩技术点讲不清。这篇拿一套我手上资料齐全的 SpringBoot 车辆管理系统（前后端分离，11 张表），从选题到答辩完整过一遍，每一段都能对照论文目录直接用。

**二、选题与选型：为什么这个方向适合毕设**

1. 业务零解释成本。管车辆、记保养、记事故，答辩页面一放老师秒懂，不用解释"这个系统是干嘛的"。
2. 模块天然工整。一辆车对应保养/事故/维修/违章四类登记，一表一模块，论文"功能设计"章每节都有东西写，工作量扎实但不失控。
3. 技术点够讲。前后端分离、REST 接口、Token 鉴权、字典配置，每个都能独立成节，比纯 CRUD 项目多一层架构话题。
4. 风险提示（诚实说）：如果连 MySQL 安装都费劲，先补环境再谈选题；拿到任何工程都先跑通再动笔，别论文写完发现环境起不来。

**三、系统功能设计：模块怎么划分**

这套系统一句话：**SpringBoot 后端提供 REST 接口 + Vue 管理端（element-ui），单一管理端、两种登录角色（管理员、员工，员工可自行注册）**。说明一下，很多同学以为要有独立前台，其实内部管理系统就一个管理端，这反而省掉一整块前台开发量。

模块清单：首页统计图表；车辆管理（名称、类型、车牌号、所属车主）；保养登记、事故登记、维修登记、违章登记四大登记模块；用户管理（车主档案：电话、身份证、准驾车型、驾驶证号）；员工管理；基础数据管理（各类字典）；个人中心与修改密码。

**加分点在字典驱动**：保养类型、车辆类型、事故类型、维修类型、违章类型、准驾车型这些下拉选项全部走 `dictionary` 表配置，管理端里改字典，业务表单的选项跟着变，不改代码。论文里把这条配置机制画成图，就是"系统总体设计"章的好插图，也直接回答老师爱问的"下拉框数据哪来的"。

**四、数据库设计：11 张表怎么分**

库名 cheliangguanli，脚本共 11 张表，拆开很清晰：

- 业务表 8 张：`cheliang`（车辆）、`baoyangdengji`（保养登记）、`shigudengji`（事故登记）、`weixiudengji`（维修登记）、`weizhangdengji`（违章登记）、`yonghu`（车主档案）、`yuangong`（员工）、`dictionary`（字典）；
- 系统表 3 张：`users`（管理员账号）、`token`（登录令牌）、`config`（系统配置）。

对数据库设计章的启发是：**成熟系统的表 = 业务表 + 少量系统表**，11 张的体量画 ER 图毫无压力。关键关系就三条：车辆挂车主（yonghu_id）、四类登记分别挂车主与员工（登记表里两个外键）、字典表统一供养所有类型字段。脚本还带示例数据（字典 35 条、车辆 12 条、四类登记各多条），导入即有数据可演示。

**五、技术实现要点：两个值钱的技术点讲透**

**1. 自定义 Token 鉴权**。登录成功后服务端生成 token 写入 `token` 表并返回给前端，之后每个请求带 token，后端用拦截器（`AuthorizationInterceptor`）统一校验、从表里换出用户身份。答辩被问"登录态怎么维持""为什么不用 Session"，就答：前后端分离后前端与管理端域名路径解耦，Token 方案无状态、跨域友好，配合拦截器做统一鉴权比每个接口手写校验干净——这个选型理由比功能本身更能体现工程素养。

**2. MyBatis-Plus 的 CRUD 提效**。单表增删改查直接继承 BaseMapper，条件构造器拼查询，分页插件管分页——四类登记模块结构几乎一致，正是"模板化开发"的现成案例。被问"为什么选 MyBatis-Plus"，答：单表场景省掉大量重复 SQL，复杂统计再手写 XML，两者结合。

顺带一个点：前后端分离（Vue + REST 接口）。被问"和传统 JSP/模板引擎项目比好在哪"，答：接口与页面解耦、可以并行开发、接口还能给小程序/App 复用——技术选型服务于扩展性。

**六、运行与部署：从导库到跑通**

环境：JDK 1.8+、Maven、MySQL 5.7 以上，Windows/macOS 均可。

步骤：
1. 导脚本：db.sql 自带建库语句，MySQL 里直接 `source db.sql` 即可；
2. 改 `src/main/resources/application.yml`：数据库用户名、密码改成你本机的；
3. 启动：`mvn spring-boot:run`；
4. 验证：端口 8080，访问 `http://localhost:8080/cheliangguanli/admin/dist/index.html`（注意带 /cheliangguanli 前缀），管理员 admin/admin，员工 a1、a2、a3/123456。

**七、踩坑与经验（真实高频问题）**

1. 直接访问 localhost:8080 打不开——context-path 是 /cheliangguanli，地址要带前缀，漏了就 404；
2. 上传图片失败——这套工程上传文件名不能带中文，重命名成英文再传；
3. 数据库连不上——九成是 application.yml 里密码没改对或 MySQL 服务没启动，先用命令行 `mysql -u root -p` 验证账号；
4. 经验之谈：先跑通再动笔；技术表述要和工程对齐（这套的论文参考是按 SSM 写的，工程实际是 SpringBoot，这个后面细说）。

**八、答辩要点：这套系统会被问什么**

- "前后端分离怎么做的"——Vue 管理端发 REST 请求，SpringBoot Controller 返回 JSON，一条请求链路（页面→接口→Service→Mapper→MySQL）画图讲清；
- "登录鉴权怎么实现"——Token 生成、存储、拦截器校验三步，一分钟讲完；
- "数据库多少张表"——11 张 = 8 业务 + 3 系统，能说出构成和三条关键关系就赢了大部分同学；
- "下拉框数据哪来的"——字典表驱动，管理端可配，现场改一个类型演示，效果很好；
- "是你自己写的吗"——别硬说从零手写。这套基于通用脚手架模板开发，建议在其上做自己的业务调整，能讲清每个模块的原理比"从零手写"的说法更经得起追问；
- "出 bug 怎么排查"——答思路：看日志定位异常堆栈 → 分层排查（请求发出没有、Controller 进没进、SQL 对不对）→ 最小复现修复。

**九、总结与引导**

车辆管理系统方向：好开题、好写论文、好答辩，前提是把前后端分离、Token 鉴权、字典配置这三个技术点吃透。丑话说前面：这套配套的论文参考和 PPT 是按 SSM 技术栈表述撰写的，而工程实际是 SpringBoot 2.2.2，拿去当参考要自己调整技术章节，别直接照搬；演示视频也没有，只有运行截图；环境（JDK/MySQL）要自己装。学习参考用没问题，论文请独立完成。

模块划分、表结构、答辩思路有疑问的，评论区留言，看到会回。想讨论怎么把这个结构套到自己题目上的，评论区一起聊。
