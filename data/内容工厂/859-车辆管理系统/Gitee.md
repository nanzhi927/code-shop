# 车辆管理系统-SpringBoot（毕设学习版）

基于 SpringBoot 的车辆管理系统**教学版**：后端 SpringBoot 提供 REST 接口，前端 Vue 管理端，前后端分离架构。业务围绕"车辆 + 保养/事故/维修/违章四类登记"闭环展开，数据库 11 张表导入即用，适合毕业设计、课程设计的学习参考与技术交流。

> 本仓库为教学版，供学习交流使用；完整版（含全部文档资料、运行说明与答疑）获取方式见文末引导。

## 项目简介

- **架构**：前后端分离。SpringBoot 2.2.2 后端暴露 REST 接口（JSON），Vue 2 + element-ui 管理端通过接口交互，`dist` 打包版直接随工程部署。
- **角色**：两种登录角色——管理员、员工（员工支持自行注册）。车主（用户）作为档案数据被管理，不参与登录。
- **数据库**：MySQL，库名 `cheliangguanli`，11 张表（业务表 8 张 + 系统表 3 张），脚本自带建库语句与示例数据，导入即用。
- **鉴权**：自定义 Token 拦截器——登录生成 token 写入 `token` 表，请求头携带，拦截器统一校验换出用户身份。

## 功能清单

### 管理端（两种登录角色：管理员 / 员工）

| 模块 | 说明 |
|---|---|
| 首页 | 统计图表，后端分组统计接口供数，按类型/数量汇总 |
| 车辆管理 | 车辆名称、车辆类型（字典）、绑定车牌号、所属车主、备注详情；增删改查、分页、条件查询 |
| 保养登记管理 | 保养名称、保养类型（字典）、保养时间、详情留档 |
| 事故登记管理 | 事故类型（字典）、责任方（我方/他方字典）、事故详情 |
| 维修登记管理 | 维修类型（字典）、维修记录全流程 |
| 违章登记管理 | 违章类型（字典）、违章记录 |
| 用户管理 | 车主档案：姓名、电话、身份证、照片、性别、准驾车型、驾驶证号、备注 |
| 员工管理 | 员工信息与账号维护（员工亦可在登录页自行注册） |
| 基础数据管理 | 字典配置：保养/车辆/事故/维修/违章类型、准驾车型、性别类型等，后台可增改，业务表单下拉项同步生效，无需改代码 |
| 个人中心 / 修改密码 | 个人信息维护、密码修改 |

角色说明：管理员可见全部菜单（含员工管理、基础数据管理）；员工侧重车辆与四类登记的日常操作。车主（yonghu 表）为档案数据，不直接登录。

## 数据库设计

库名 `cheliangguanli`，共 11 张表，按用途分两类：

| 分类 | 数量 | 表与说明 |
|---|---|---|
| 业务表 | 8 张 | `cheliang` 车辆、`baoyangdengji` 保养登记、`shigudengji` 事故登记、`weixiudengji` 维修登记、`weizhangdengji` 违章登记、`yonghu` 车主档案、`yuangong` 员工、`dictionary` 字典 |
| 系统表 | 3 张 | `users` 管理员账号、`token` 登录令牌、`config` 系统配置 |

关键关系：车辆表 `yonghu_id` 挂车主；四类登记表同时挂 `yonghu_id` 与 `yuangong_id`（谁的车、谁经手）；`dictionary` 表统一供养所有类型字段的下拉项。脚本自带示例数据（字典 35 条、车辆 12 条、四类登记各多条、员工 3 条、管理员 1 条），导入即有数据可演示，重复导入前请先 DROP（脚本已含 DROP 语句）。

ER 图建议按"车主—车辆—四类登记"主链路画，字典表单独配一张"类型配置关系"小图即可。

## 快速开始

第 1 步：导入数据库（db.sql 自带建库语句）

```sql
source 你的路径/db.sql;
```

或命令行直接导入：

```bash
mysql -u用户名 -p < db.sql
```

导入后应能看到 11 张表；表数量不足说明脚本未导完，重新导入即可。

第 2 步：修改配置。打开 `src/main/resources/application.yml`：
- 数据库用户名、密码改成你本机的（默认 root/123456）；
- 端口默认 8080，context-path 为 `/cheliangguanli`，一般无需改动。

第 3 步：启动

```bash
mvn spring-boot:run
```

或在 IDEA 中直接运行 `cheliangguanliApplication`。

第 4 步：访问验证

- 管理端地址：`http://localhost:8080/cheliangguanli/admin/dist/index.html`（注意：必须带 `/cheliangguanli` 前缀，直接访问 8080 会 404）
- 管理员账号：admin / admin
- 员工账号：a1、a2、a3 / 123456（也可在登录页自行注册）

看到启动完成日志、登录页正常打开即运行成功。

## 常见问题（FAQ）

**Q1：直接访问 localhost:8080 打不开（404）？**
context-path 是 `/cheliangguanli`，完整地址必须带前缀：`http://localhost:8080/cheliangguanli/admin/dist/index.html`。

**Q2：启动报数据库连接失败（Access denied / Communications link failure）？**
九成是 application.yml 里数据库密码/用户名没改对，或 MySQL 服务未启动。先在命令行用同样账号密码登录 MySQL 验证。

**Q3：上传图片失败？**
这套工程上传的图片文件名不能包含中文，把文件重命名为英文/数字再上传。

**Q4：Maven 依赖下载慢或工程报红？**
配置国内镜像源（如阿里云 Maven 镜像），删除本地仓库中下载不完整的目录后重新 update；IDEA 导入后等待依赖全部下载完成再看报错。

**Q5：登录角色有几种？车主怎么登录？**
两种登录角色：管理员、员工。车主（yonghu 表）是档案数据，没有登录账号字段，不直接登录——这是这套系统的设计，不是缺功能。

**Q6：为什么 pom 里有 Shiro 依赖？**
依赖随模板带入，代码中未实际启用；实际鉴权是自定义 Token 拦截器（登录生成 token 存 `token` 表，拦截器统一校验）。

**Q7：字典下拉项在哪里改？**
管理端"基础数据管理"里集中配置：保养/车辆/事故/维修/违章类型、准驾车型、性别类型等，改完业务表单下拉项即时生效，无需改代码。

**Q8：这个项目能用作毕业设计吗？**
可以作学习参考。建议在其上做自己的业务调整（如加年检登记、油卡管理），答辩时如实说明基于通用模板二次开发，能讲清每个模块的原理比"从零手写"的说法更稳。

**Q9：配套论文和 PPT 能直接用吗？**
不能直接照搬。随包的论文（Word）与 PPT 是按 SSM 技术栈表述撰写的，工程实际为 SpringBoot 2.2.2，技术章节需自行调整；论文请独立完成，这里仅作结构与写法参考。

**Q10：支持哪些系统？MySQL 8 可以吗？**
Windows / macOS 均可；运行必读口径为 MySQL 5.7 及以上，建议 5.7 验证过的版本优先。
