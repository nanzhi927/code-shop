# 旅游网站管理系统-SpringBoot（毕设学习版）

基于 SpringBoot 的旅游网站**教学版**：前台用户端 + 后台管理端双入口，业务链完整——浏览线路、收藏评论、购物车、预订、模拟支付、订单管理，前后端分离架构，数据库 15 张表导入即用，适合毕业设计、课程设计的学习参考与技术交流。

> 本仓库为教学版，供学习交流使用；完整版（含全部资料与运行说明）获取方式见文末引导。

## 项目简介

- **架构**：前后端分离——后端 SpringBoot 2.2.2 提供 REST 接口，前台为 Vue + ElementUI 静态页面，后台为 Vue 2.6 + Element UI 2.13 管理端（两者均为构建产物，运行无需 Node 环境）。
- **双端**：前台 `/front/index.html` 面向用户（浏览、预订），后台 `/admin/dist/index.html` 面向管理员（数据维护、订单处理）。
- **数据库**：MySQL，库名 `springbootmt74k`，15 张表（系统表 3 张 + 业务表 12 张），脚本自带建库语句与真实感示例数据（云南大理丽江 6 天 5 晚、桂林 4 天 3 晚等），导入即用。
- **工程**：标准 Maven 结构，JDK 1.8。

## 数据库设计

库名 `springbootmt74k`，共 15 张表，按用途分四域：

| 域 | 表 | 说明 |
|---|---|---|
| 系统域（3） | `users` / `token` / `config` | 管理员账号、登录令牌、轮播与全局配置 |
| 内容域（4） | `lvyouxianlu` / `zuixinxianlu` / `xianlufenlei` / `news` | 旅游线路、最新线路、线路分类、新闻资讯 |
| 交易域（3） | `cart` / `orders` / `address` | 购物车、订单（含商品快照与状态）、收货地址 |
| 互动域（4） | `storeup` / `discusslvyouxianlu` / `discusszuixinxianlu` / `chat` | 收藏、两类线路评论、在线客服 |
| 账户域（1） | `yonghu` | 前台用户（含余额字段） |

脚本包含建库语句与示例数据，重复导入不冲突。ER 图建议按域绘制：内容域一张（分类-线路-评论）、交易域一张（用户-购物车-订单-地址），两张图讲清全貌，别把 15 张表挤一张图里。

## 快速开始

第 1 步：导入数据库

```sql
create database springbootmt74k default character set utf8;
use springbootmt74k;
source 你的路径/db.sql;
```

或命令行直接导入：

```bash
mysql -u用户名 -p springbootmt74k < db.sql
```

导入后应能看到 15 张表；表数量不足说明脚本未导完，重新导入即可。

第 2 步：修改配置。打开 `src/main/resources/application.yml`：
- 数据库连接：用户名、密码改成你自己的（默认 root / 123456）；
- 端口：默认 8080，被占用可修改 `server.port`；
- 上下文路径 `/springbootmt74k` 保持默认即可。

第 3 步：启动

```bash
mvn spring-boot:run
```

或在 IDEA 中导入 Maven 工程后运行启动类 `SpringbootSchemaApplication`。

第 4 步：访问验证（推荐 Chrome）
- 前台：`http://localhost:8080/springbootmt74k/front/index.html`
- 后台：`http://localhost:8080/springbootmt74k/admin/dist/index.html`（账号信息见完整版运行说明）
- 注意地址中间的 `/springbootmt74k` 上下文路径不要遗漏，直接访问 8080 会 404；前后台是两个不同入口

看到启动完成日志即运行成功。

## 常见问题（FAQ）

**Q1：启动报数据库连接失败（Access denied / Communications link failure）？**
九成是 application.yml 里数据库密码/用户名没改对，或 MySQL 服务未启动。先在命令行用同样账号密码登录 MySQL 验证。

**Q2：打开 localhost:8080 是 404？**
漏了上下文路径，且前后台是两个入口：前台 `front/index.html`、后台 `admin/dist/index.html`，完整地址见上文。

**Q3：报端口被占用（Port 8080 was already in use）？**
把 `server.port` 改成 8081 等未占用端口，或找到占用进程处理。

**Q4：需要安装 Node.js 吗？**
不需要。前台页面与后台管理端均为构建产物，运行只需 JDK + MySQL。

**Q5：支付是真的吗？**
模拟支付：通过余额充值（yonghu 表余额字段）完成扣款，订单状态在未支付/已支付/已完成间流转。学习项目不建议接真实支付，讲清状态机设计即可。

**Q6：前台为什么要登录？**
收藏、评论、购物车、预订等操作会校验 token；示例用户数据在 yonghu 表，可自行注册新用户。

**Q7：这个项目能用作毕业设计吗？**
可以作学习参考。代码为代码生成器风格脚手架二次开发，建议在其上做自己的业务定制，答辩时如实说明，能讲清原理比"从零手写"的说法更稳。

**Q8：有论文或开题报告吗？**
工程资料含论文参考文档、开题报告参考与 PPT 素材，仅供学习参考。论文请自己撰写，技术实现思路可以交流。

**Q9：支持哪些系统？MySQL 8 可以吗？**
Windows / macOS 均可；MySQL 5.7 / 8.0 都支持。

**Q10：想把前台改成自己的业务（如景区门票）怎么改？**
线路相关表和页面结构是通用的"内容+交易"模型，替换字段与文案即可；具体思路可在 Issues 交流。

## 学习与答辩参考

拿这套系统做毕设参考的同学，建议按这条线准备：

1. **先跑通再动笔**：环境搭好、前后台各登录一遍，按业务链走一遍（浏览→加购→预订→支付→后台发货），全程截图，论文素材一次凑齐；
2. **技术点吃透两个**：订单流程（购物车→订单含商品快照→模拟支付→发货，讲清为什么快照冗余）和前后端分离（接口设计与双端数据流），答辩被追问就围绕这两个展开；
3. **数据库按域讲**：15 张表 = 系统 3 + 内容 4 + 交易 3 + 互动 4 + 账户 1，按域分组说清构成，本身就是加分项；
4. **演示提前彩排**：前台预订、后台发货这个双端联动操作现场演示一遍，效果很好；
5. **如实说明来源**：基于生成器风格脚手架二次开发，能讲清每个模块的原理，比"从零手写"的说法更经得起追问。
