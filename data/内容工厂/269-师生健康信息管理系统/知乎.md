### 正文（1500-3000 字干货长文，9 段结构）

**一、背景：毕设真正的卡点不是代码**

先说结论：师生健康信息管理是 Java 毕设里"场景好讲、角色天然、工作量可控"的方向，适合大部分普通水平的同学。

自己做毕设、也陪同学踩过一圈坑，发现真正的卡点从来不是"不会写代码"，而是三件事：选题开题说不清系统长什么样、拿到工程跑不起来、答辩技术点讲不清。这篇拿一套我实测跑通的 SpringBoot 师生健康信息管理系统（三角色、12 张表），从选题到答辩完整过一遍，每一段都可以直接对照论文目录用。

**二、选题与选型：为什么这个方向适合毕设**

1. 业务零解释成本。疫情之后"健康打卡、问卷填报、返校审批"是每个人都经历过的场景，答辩页面一放，老师秒懂这个系统是干嘛的。
2. 角色天然。管理员/教师/学生三种角色是业务自带的，不用硬凑"多角色权限设计"这种技术点——论文的权限设计章有现成素材。
3. 业务链完整。问卷发布→在线填报→数据采集→返校统计，一条链把增删改查、统计分析都串起来了，每个环节都能在论文里独立成节。
4. 工作量可控。数据库 12 张表，ER 图画得完、讲得清，不会像几十上百张表的项目那样把自己绕进去。
5. 风险提示（诚实说）：如果连 MySQL 安装都费劲，先补环境再谈选题；拿到任何工程务必先跑通再写论文。

**三、系统功能设计：模块怎么划分**

这套系统一句话：**一个入口、三种角色、一条健康信息管理业务链**。这个划分天然对应论文三章结构：角色与权限（系统安全设计章）、业务流程（功能实现章）、数据统计（系统分析章）。

管理员 10 组功能：学生管理（学号/姓名/学院/专业/联系电话）、教师管理（工号/姓名/身份证/职称/联系电话）、数据收集管理（住址/体温/身体状况）、问卷分类管理、疫情问卷管理、问卷调查管理、返校信息管理（详情/下载/统计报表）、数据采集管理、返校情况管理、个人中心。

教师端 5 组：个人中心、疫情问卷（新增/在线作答）、问卷调查管理、数据采集查看、返校情况管理。

学生端 4 组：个人中心、数据收集填报、疫情问卷在线作答、返校信息管理。

**加分点在业务链**：管理员发布疫情问卷 → 学生在线作答提交 → 问卷调查管理里汇总填报信息 → 结合返校情况生成统计报表。论文里把这条数据流画成图，就是"系统总体设计"章的核心插图，也回答了老师爱问的"你这个系统的核心业务是什么"。

**四、数据库设计：12 张表怎么分类**

库名 springboot43q56，脚本共 12 张表，拆开很清晰：

- 系统表 3 张：users（管理员账号）、token（登录令牌）、config（全局配置）；
- 业务表 9 张：jiaoshi（教师）、xuesheng（学生）、yiqingwenjuan（疫情问卷）、wenjuandiaocha（问卷调查）、wenjuanfenlei（问卷分类）、fanxiaoxinxi（返校信息）、fanxiaoqingkuang（返校情况）、shujucaiji（数据采集）、xinxicaiji（信息采集）。

给数据库设计章的启发：**表不在多，在于每个角色、每个业务环节都有落点**。12 张表按"角色表（2）→ 问卷域（3）→ 返校域（2）→ 采集域（2）→ 系统表（3）"分组讲，比堆数量更显设计能力。ER 图建议按角色画中心（管理员-教师-学生），问卷、采集、返校三类业务挂在对应角色下，一张主图讲清全貌。

**五、技术实现要点：两个值钱的技术点讲透**

**1. 多角色权限（Shiro + 拦截器）**。这套系统用 Apache Shiro 1.3.2 做认证授权：三种角色同一登录入口，登录后按角色下发 token、加载不同的菜单。答辩被问"权限怎么做的"，就按"认证（你是谁）→ 授权（你能看什么）→ 拦截（没登录的请求拦下来）"三步讲，一分钟讲完。被问"为什么不用 Spring Security"，答：Shiro 轻量、上手快、对中小系统够用——选型理由比功能本身更能体现工程素养。

**2. 前后端分离（SpringBoot + Vue）**。后端 SpringBoot 2.2.2 + MyBatis-Plus 2.3 出 REST 接口，前端 Vue 2.6 + Element UI 2.13 + ECharts 4.6 管理端，通过 axios 交互。亮点：工程里已经带构建好的前端产物，改完代码重启就能看效果，不用装 Node 环境。被问"为什么前后端分离"，答：接口复用（未来可接小程序/App）、前端后端可并行开发、职责清晰——每个理由都站得住。

顺带一个点：MyBatis-Plus 的通用 CRUD 和条件构造器，让 9 张业务表的增删改查代码量大幅减少，可以写进"开发效率"小节。

**六、运行与部署：从导库到跑通**

环境：JDK 1.8+、MySQL 5.7/8.0，Windows/macOS 均可，不需要 Node。

步骤：
1. 导入数据库：db.sql 自带建库语句，或 `create database springboot43q56 default character set utf8;` 后 source 导入，导完应看到 12 张表；
2. 改 `src/main/resources/application.yml`：数据库用户名、密码改成你自己的（默认写的 root/123456）；
3. 启动：IDEA 导入 Maven 工程运行主类，或 `mvn spring-boot:run`；
4. 验证：浏览器（推荐谷歌）访问 `http://localhost:8080/springboot43q56/admin/dist/index.html`，管理员账号 abo 登录，三种角色菜单都能看。

**七、踩坑与经验（真实高频问题）**

1. 打开 localhost:8080 白页/404：九成是漏了上下文路径 /springboot43q56，完整地址要以运行说明里的为准；
2. 数据库连接失败（Access denied）：配置文件里密码没改对，或 MySQL 服务没启动，先用命令行验证账号能不能登；
3. 端口被占用（Port 8080 was already in use）：改 application.yml 的 server.port；
4. 经验之谈：先跑通再动论文；三种角色各登录一遍截图，论文截图素材一次凑齐。

**八、答辩要点：这套系统会被问什么**

- "权限怎么做的"——Shiro、token、三角色菜单区分，按认证→授权→拦截讲；
- "数据库多少张表"——12 张 = 系统 3 + 业务 9，能按角色和业务域分组说清就赢了大部分同学；
- "为什么选这个技术栈"——SpringBoot 2 稳定、MyBatis-Plus 提效、Vue Element 界面规范，每个都有具体理由；
- "核心业务是什么"——按"问卷→填报→统计→返校"那条链讲，配合现场演示学生填报、管理员看报表；
- "出 bug 怎么排查"——看日志定位异常堆栈→分层排查（前端请求有没有发出、Controller 有没有进、SQL 对不对）→最小化复现修复。

**九、总结与引导**

健康管理方向：场景好讲、三角色权限现成、业务链完整，前提是把权限、表构成、业务流转三个点吃透。我这套实测跑通过，工程+数据库脚本+说明文档齐全，还自带论文参考文档和 PPT 素材（注意：仅供参考，自己的论文要自己写）。丑话说前面——工程里没有录屏演示视频，环境要自己装。
