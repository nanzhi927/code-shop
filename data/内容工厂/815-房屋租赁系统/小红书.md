### 正文（800-1200 字）

开题描述半天说不清系统长什么样的同学，真心推荐看一眼"房屋租赁"这个方向：业务人人懂（租房谁没租过？），答辩页面一放老师就明白。今天把我跑通的一套 SpringBoot 房屋租赁系统完整拆开讲：功能、技术栈、数据库、踩过的坑一次说清，准备开题和答辩照着这个思路来就够。

**为什么推荐这个选题**✅
1. 业务零解释成本：找房、看房、签约、报修，流程大家都经历过，讲起来不用铺垫；
2. 三角色闭环：管理员、用户、房主，比普通"单角色+几张表"的系统业务链长，工作量看着扎实；
3. 技术点够用不深奥：SpringBoot + MyBatis-Plus + Shiro，权限和业务流程两条线都能在答辩里展开。

**功能逐条列全**（这套是前台+后台完整实现）
前台 6 个栏目👇
✅ 首页：系统核心内容与轮播展示
✅ 房屋信息：可租房源列表，含月租金、押金、面积、朝向楼层、小区、设施
✅ 我要当房主：用户提交自己的房源，走申请流程
✅ 公告信息：系统公告展示
✅ 留言反馈：留言板，可互动
✅ 个人中心：资料与密码管理

后台按角色分三块👇
✅ 管理员 13 组：用户管理、房主管理、房屋类型、房屋信息、预约看房、合同信息、房屋报修、维修处理、房屋评价、我要当房主审核、留言板、系统管理（轮播图/公告）、个人中心
✅ 用户端 8 项：预约看房、合同信息、房屋报修、维修处理跟踪、房屋评价、我要当房主申请、我的收藏、个人中心
✅ 房主端 7 项：发布/管理自己的房源、审核预约看房、管理合同、处理报修、跟进维修、查看回复评价、个人中心

重点是**业务主线**：预约看房 → 审核通过 → 生成合同（月租、押金、租用月数、合同金额，带支付状态）→ 入住后报修 → 维修处理（维修中/已完成）→ 退租后房屋评价。答辩现场把这条链从头演示一遍，比背十页稿子都管用。

**技术栈与版本**
SpringBoot 2.2.2 + MyBatis（starter 2.1.1）+ MyBatis-Plus 2.3 + Apache Shiro 1.3.2 + FastJSON + Hutool，JDK 1.8；后台 Vue + Element-UI（已带构建产物），前台静态页（layui/Element-UI）。主流组合，学过 SSM 上手很快。

**数据库**
库名 springboot08hr3，脚本自带 **18 张表**：系统支撑 3 张（配置/令牌/管理员）+ 公告留言 2 张 + 租赁业务 13 张（房屋信息、房屋类型、房主、用户、预约看房、合同、报修、维修处理、评价、我要当房主、评论×2、收藏）。含建表语句和示例数据，导入即用，ER 图那章素材管够。

**这套工程包含什么**
完整 Maven 工程、db.sql 数据库脚本（18 张表+示例数据）、说明文档、运行必读、运行截图 13 张、PPT 一份。
⚠️ 丑话说前面：**论文文档是没有的**（只有论文截图），论文要自己写；环境（JDK/MySQL）也要自己装；演示视频也没有。

**运行门槛**
装 JDK 1.8 + Maven + MySQL 5.7+，建库导脚本，改 application.yml 里的数据库密码，启动主类就起来了。默认端口 8080，前台 /front/index.html，后台 /admin/dist/index.html。

**我踩过的坑**
1. 后台是 Vue 工程，改了前端要重新 build，别改了源码刷新页面没反应就怀疑人生；
2. 数据库密码忘改是最常见报错，先命令行验证账号能登再启动；
3. 先跑通再动论文，演示提前彩排一遍业务主线。
