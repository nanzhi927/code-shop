## 一、开源引流策略（近期主线）

### 1.1 免费版 vs 付费版（分层，不做欺骗式钓鱼）
| 层 | 放哪 | 内容 | 目的 |
|---|---|---|---|
| **开源版（免费）** | Gitee / GitHub | **精简可跑版**：完整框架 + 核心 1-2 个模块 + 数据库脚本 + README + 演示录屏 | 涨 Star、建技术信誉、引流到自建站 |
| **完整版（付费）** | 自建站 | 完整工程 + 完整脚本 + 运行说明 + 截图 + 录屏 + 部署服务 + 讲解 | 成交 |
| **定制层（高价）** | 自建站 / 私域 | 改功能、加模块、换技术栈、远程部署、1v1 讲解 | 利润核心 |

**强制**：README 必须写明"开源版包含什么 / 不包含什么"（诚实，避免差评）。

### 1.2 开源仓库包（每个项目产出物）
1. **精简版代码包**（可编译、可运行、可演示；不随机删文件）
2. `README.md`（中文）：项目简介 → **引流区（站点链接，置顶与结尾各一处）** → 功能清单 → 技术栈 → 目录结构 → 快速开始（命令）→ 常见问题 → 免责声明与许可
3. `LICENSE` + 免责声明（仅供学习、不含商业授权、来源说明）
4. 演示录屏/截图（放 `docs/`）
5. 脱敏检查（学校/学号/姓名/论文/教师信息全部清除）

### 1.3 选品标准（哪些项目适合开源）
- ✅ 技术主流（SpringBoot / SSM / Vue / 小程序）
- ✅ 结构清晰、能跑通（有 事实卡 或已验证）
- ✅ **可脱敏、来源清晰**（你自己写的或已获授权）——**转售他人的源码不上传**
- ✅ 有讲解视频的优先（演示效果好）
- 目标：**首批 5 个**，验证效果后每周 2-3 个，累计 20-30 个

### 1.4 账号与发布
- Gitee / GitHub 账号资料：技术向昵称与简介，主页放站点链接（GitHub 无需合规词限制，Gitee 同理，均正常写）
- 仓库命名：`{业务名}-{技术栈}`（如 `enterprise-portal-springboot`）
- Topics/标签：`springboot` `java` `management-system` `learning-project`
- 节奏：每周 2-3 个仓库；每个仓库配 1 条技术说明（可选）
- 站内配合：自建站新增"开源项目"页，列出全部仓库（与仓库互引）

### 1.5 度量
Star 数 / 仓库访问量 / README 链接点击（用站点 utm 参数区分来源）

## 五、风险与红线（不可越）
1. **著作权**：只开源自己写的/已授权的项目；转售的他人源码不上传公开仓库
2. **脱敏**：学校、学号、姓名、论文正文、教师信息必须清除
3. **不做欺骗**：不用"伪装成纯技术内容"的方式绕过平台审核；免费版范围如实写明
4. **学术不端**：不做代做/代写/包过类内容
5. **开源许可**：README 写清许可与来源，尊重原项目 LICENSE
