# 免费开题 · 产品与技术方案

> 版本：v1.2 ｜ 日期：2026-09-05 ｜ 状态：P0/P1/P2 核心已落地（人机验证/队列可选增强待做）  
> 定位：前台「增值服务」下的**免费引流能力** —— 用户通过「上传开题模板」或「问答收集需求」，由 AI 生成开题报告初稿，并自然导流到源码购买 / 定制开发。

---

## 一、背景与目标

### 1.1 为什么做

| 动机 | 说明 |
|------|------|
| 用户刚需前置 | 多数买家在买源码前先要过「开题」关；站内目前没有相关工具 |
| 免费获客 | 用低摩擦免费工具换留存与线索，再转化到源码/定制 |
| 差异化 | 竞品多为纯卖源码；「开题助手」可形成记忆点 |
| 数据闭环 | 开题选题、技术栈、模块需求可反哺选题趋势与定制线索 |

### 1.2 目标（可验收）

1. 用户 **5 分钟内**可完成「信息收集 → 生成 → 预览/下载」。
2. 支持两条入口：**模板驱动**、**问答驱动**（可混合）。
3. 产出物为结构化开题报告（Markdown / Word / 复制），章节完整、可读、可改。
4. **免费有限额**（防刷）：手机号注册一次性赠送次数，用完引导联系客服。
5. 文案与流程明确：**仅供学习参考，禁止学术不端**；不承诺替写、不包过审。

### 1.3 非目标（本期不做）

- 不做人机实时语音答辩辅导。
- 不做整篇毕业论文一键生成。
- 不做学校教务系统对接。
- 不保证「百分百符合某校模板格式」（模板解析做「尽力而为」+ 人工可改章节）。

## 二、产品定位与入口

### 2.1 产品名建议

- 对外名称：**免费开题助手**
- 路径：`/services/proposal`（或 `/services/kaiti`）
- 服务列表卡片：挂在「增值服务」首位或次位（引流）
- 落地页：可复用 `/services/p/proposal` 介绍页，CTA → 助手工作台

### 2.2 与现有业务关系

```
免费开题助手 ──推荐──▶ 站内相关源码（按选题/技术栈）
        │
        ├──转化──▶ 定制开发工单（功能范围清晰后）
        │
        └──引流──▶ 联系客服 / 答辩 PPT / 代跑部署
```

### 2.3 用户旅程总览

```
进入助手页
   │
   ├─路径 A：上传学校开题模板（docx/pdf）→ 解析章节结构
   ├─路径 B：问答向导（选题、方向、技术栈、功能点…）
   └─路径 C：A + B 混合（模板定结构，问答补内容）
   │
   ▼
确认「报告大纲」与关键字段（可编辑）
   │
   ▼
AI 分段生成（流式输出）→ 组装全文
   │
   ▼
预览 / 复制 / 导出 Word / 保存到「我的开题」
   │
   ▼
推荐相关源码 +「需要二次开发？去定制」
```

## 三、信息架构与页面设计

### 3.1 前台页面

| 页面 | 路径 | 说明 |
|------|------|------|
| 介绍落地页 | `/services/p/proposal` | 卖点、流程、免责声明、开始按钮 |
| 开题工作台 | `/services/proposal` | 核心：选模式 → 收集 → 大纲 → 生成 → 结果 |
| 我的开题 | `/services/proposal/mine` | 登录用户历史记录（可选 P1） |

建议：**强制手机号注册登录后生成**；注册一次性赠送 N 次（后台可配）；游客仅可浏览说明，不可生成。

### 3.2 工作台分步 UI（Wizard）

1. **选择方式**：上传模板 / 智能问答 / 两者结合  
2. **收集信息**  
   - 上传区：拖拽 docx/pdf，展示解析出的章节树  
   - 问答区：分步表单 + 进度条（非聊天刷屏，降低成本）  
3. **确认大纲**：章节可增删改排序；缺项高亮  
4. **生成中**：流式展示当前章节；可暂停（P2）  
5. **结果页**：全文预览、章节锚点、导出、相关商品推荐  

移动端：单列步骤条；上传与问答用 Tab；结果页底部固定「导出 / 再生成」。

### 3.3 问答字段设计（结构化，便于 Prompt）

| 字段 | 必填 | 示例 |
|------|------|------|
| 题目 / 暂定题目 | 是 | 基于 SpringBoot 的校园失物招领系统 |
| 专业 / 学历层次 | 是 | 软件工程 · 本科 |
| 技术栈偏好 | 是 | SpringBoot + Vue + MySQL |
| 业务领域 | 是 | 校园 / 电商 / 医疗… |
| 核心功能模块（3～8 个） | 是 | 用户、失物发布、认领审核… |
| 研究背景一句话 | 否 | 校园失物找回效率低 |
| 创新点 / 特色 | 否 | 消息推送 + 相似度匹配 |
| 学校模板特殊要求 | 否 | 必须含「可行性分析」「进度安排」 |
| 字数/页数期望 | 否 | 约 3000 字 / 8～10 页 |
| 参考资料偏好 | 否 | 近 5 年中文文献为主 |

问答可用「选择题 + 短填空」为主，减少用户打长文；功能模块支持从站内同类商品「一键带入模块列表」（复用 `details` / 功能结构）。

### 3.4 默认开题报告章节（无模板时）

1. 选题背景与意义  
2. 国内外研究现状  
3. 研究内容与目标  
4. 研究方法与技术路线  
5. 系统需求分析（功能/非功能）  
6. 总体设计思路（架构、模块）  
7. 可行性分析（技术/经济/操作）  
8. 进度安排  
9. 预期成果  
10. 参考文献（AI 生成「格式示例 + 占位」，需标注「请自行核验」）  

有模板时：**以解析章节为准**，缺省字段用问答补齐。

## 四、核心流程设计

### 4.1 路径 A：模板上传

```
上传文件 → 病毒/类型/大小校验 → 存 uploads/proposal/
  → 解析器（docx 优先，pdf 次之）
  → 抽出：标题样式层级 / 编号标题 / 目录页
  → 得到 Outline[] { id, title, level, hint? }
  → 用户确认/编辑大纲
```

**解析策略（务实）**

| 格式 | 方案 | 可靠度 |
|------|------|--------|
| docx | `mammoth` / `docx` 抽段落 + 标题样式 | 高 |
| pdf | `pdf-parse` 抽文本 + 正则识别「一、」「1.」等 | 中 |
| 解析失败 | 降级为「默认章节」+ 提示用户手动改大纲 | 兜底 |

不追求完美版式还原；**结构正确 > 格式像素级一致**。

### 4.2 路径 B：问答

```
逐步收集字段 → 前端校验 → POST /api/proposal/sessions
  → 后端生成 draft outline（规则模板，不必调 AI）
  → 用户确认大纲 → 再触发 AI 撰写
```

大纲可用规则生成（省成本、稳）；正文用 AI。

### 4.3 AI 撰写流水线（关键）

```
输入：
  - outline[]
  - profile（问答字段 JSON）
  - template_hints（模板原文片段，可选，截断）
  - style（学术、本科毕设口吻）

处理：
  1. 系统 Prompt：角色、约束、禁抄袭声明、禁止编造精确数据/虚假文献 DOI
  2. 按章节串行或小批量并行生成（建议串行流式，易控 Token）
  3. 每章输出 Markdown；服务端落库 chapter 状态
  4. 全文组装 + 后处理（去重复标题、统一用语）
  5. 可选：二次「润色/压缩」Pass（P2）

输出：
  - content_md
  - content_html（可选）
  - export_docx（异步任务生成）
```

**流式**：SSE（`text/event-stream`）推送 `chapter_start` / `delta` / `chapter_done` / `done` / `error`。

### 4.4 与源码商城联动

生成完成后：

- 按 `tech` + 题目关键词检索 `/api/products?keyword=&tech=&pageSize=6`
- 展示「可用作实现底座的源码」
- CTA：「用该源码二次开发」→ 预填定制工单标题/描述
- CTA：「联系客服润色/按校模板排版」→ 打开联系弹窗

## 五、AI 与工程架构

### 5.1 Provider 抽象（与支付 Provider 同思路）

```
server/src/lib/ai/
  provider.js          # 接口：chat / chatStream
  providers/openai.js  # OpenAI 兼容协议（可接官方 / DeepSeek / 通义兼容网关）
  providers/mock.js    # 本地无 Key 时返回样例段落
  proposalPrompt.js    # 开题专用 Prompt 组装
  outline.js           # 默认大纲与模板合并
  exportDocx.js        # Markdown → docx
```

配置（`.env`，勿入库）：

```
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://api.deepseek.com
AI_API_KEY=***
AI_MODEL=deepseek-chat
AI_TIMEOUT_MS=120000
AI_MAX_OUTPUT_TOKENS=4096
```

后台「系统设置」可后续增加：模型名、日限额、是否启用免费开题（开关）。

### 5.2 成本与限流策略（免费必做）

| 层级 | 规则建议 |
|------|----------|
| 未登录 | 不可生成，引导手机号注册 |
| 新注册用户 | 一次性赠送 **N 次**（默认 3，后台 `proposal_register_gift`） |
| 用尽后 | 联系客服加次（后续可接会员） |
| 单次 | 最多 N 章；总输出 Token 上限；超时熔断 |
| 全站 | 并发队列（如同时生成 ≤ 5）；超限排队或提示稍后 |
| 防刷 | `rateLimit` + 人机验证（可选 Turnstile）+ 同内容哈希去重 |

超额文案：引导次日再来 / 加客服加次 / 购买任意源码送 1 次（运营可配）。

### 5.3 安全与合规

1. **学术诚信声明**：页首、提交前勾选、导出页脚水印「仅供学习参考」。  
2. **禁止承诺**：不出现「包过」「百分百原创检测通过」等话术。  
3. **参考文献**：明确「示例格式，请自行检索替换」；Prompt 禁止捏造 DOI/期刊卷期。  
4. **上传文件**：仅 docx/pdf；大小 ≤ 5～10MB；不执行宏；隔离存储。  
5. **隐私**：模板与生成内容默认仅本人可见；后台可审计滥用。  
6. **日志**：记录 session_id、user_id、token 用量、耗时，不含完整 Prompt 中的敏感 Key。

## 七、API 设计（草案）

前缀：`/api/proposal`

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/sessions` | 可选登录 | 创建会话（含 profile / mode） |
| POST | `/sessions/:id/template` | 可选 | 上传模板 multipart |
| POST | `/sessions/:id/outline` | 可选 | 保存/更新大纲 |
| POST | `/sessions/:id/generate` | 可选 | 触发生成（校验限额） |
| GET | `/sessions/:id/stream` | 可选 | SSE 流式结果 |
| GET | `/sessions/:id` | 本人/guest_key | 查询详情 |
| GET | `/mine` | 登录 | 历史列表 |
| GET | `/sessions/:id/export.docx` | 可选 | 导出 |
| GET | `/admin/sessions` | 管理员 | 列表/用量 |
| POST | `/admin/settings` | 管理员 | 限额与开关 |

## 九、提示词原则（摘要）

系统角色：

- 你是高校毕设「开题报告」写作助手，面向本科/专科常见要求。  
- 根据用户提供的题目、技术栈、模块生成**原创表述**的初稿。  
- 语气正式、条理清晰；避免营销腔。  
- **不得**编造具体实验数据、真实用户调研百分比、不存在的论文。  
- 参考文献只给「检索方向与格式示例」，并提醒用户自行核实。  
- 每一章紧扣用户模块，不要写空洞正确的废话堆砌。  
- 输出纯 Markdown，使用指定章节标题。

用户消息：注入 `profile` + 当前章节标题 + 前后章摘要（防重复）。

## 十一、风险与对策

| 风险 | 对策 |
|------|------|
| AI 胡编文献/数据 | Prompt 硬约束 + UI 醒目提示 + 不生成假 DOI |
| 学术不端投诉 | 免责声明、水印、仅「初稿助手」定位 |
| Token 成本飙升 | 限额、章节上限、缓存同 profile 哈希、队列 |
| 模板解析不准 | 可编辑大纲 + 失败降级默认结构 |
| 无 API Key 环境 | mock Provider + 文档说明配置方式 |
| 与「代写」灰色联想 | 文案强调学习辅助；不提供「降重套餐」入口 |
