============================================================
 code-shop 部署包  使用说明  （v3）
============================================================

【这个包是做什么的】
  把最新代码部署到服务器上【已有的安装目录】并重启服务。
  商品图片在安装目录的 server\uploads 下（约 2GB），无法随包分发，
  所以脚本不会新建站点，而是就地更新：只替换代码，保留图片与依赖。

【网站突然打不开了？先看这里】
  如果站点访问不了（浏览器连不上 / 转圈超时），但服务器还能远程桌面进去，
  说明多半是 node 进程没了。常见原因：你【注销登录】结束了远程桌面会话。
  用控制台窗口（启动.bat）跑起来的 node 属于当前登录会话，
  一旦注销（注意：只是"断开连接"没关系，注销才会杀进程）或重启服务器，它就被结束。

  两种处理：
  A. 临时拉起（马上能访问，但下次注销还会掉）：
       双击安装目录下的 启动.bat
  B. 一劳永逸（推荐，做一次就行）：
       右键本包里的「注册服务.bat」-> 以管理员身份运行
     它会把站点注册成计划任务 code-shop-server：
       · 以 SYSTEM 身份运行，与你是否登录无关
       · 开机自动启动
       · 日志写到 安装目录\server\logs\service.log
     之后用「启动服务.bat」/「停止服务.bat」控制，不会再因为注销而掉线。

  注意：已经在用计划任务托管时，本部署脚本仍然可用
  （它会结束占用端口的旧进程，再按原方式启动）。

【最重要的一条：解压到哪里】
  ✅ 解压到【和安装目录不同】的一个新文件夹，例如：
        C:\shop-update          （推荐）
        C:\Users\Administrator\Desktop\code-shop-update
  ❌ 不要把本包解压进安装目录本身，也不要让两个文件夹合并。
     如果你解压到已有文件夹，Windows 会问是否替换同名文件；
     一旦选了"跳过"，盘上代码仍然是旧的（新文件会进去，但同名文件不会覆盖），
     表现就是"部署完网站还是老样子"。

【怎么用】
  1. 把本包解压到一个【新的】空文件夹
  2. 右键「一键部署.bat」-> 以管理员身份运行
     （或在管理员 PowerShell 里执行:
        powershell -ExecutionPolicy Bypass -File .\deploy.ps1 ）
  3. 脚本自动完成 9 步，并在桌面生成日志文件
  4. 浏览器按 Ctrl+F5 强制刷新

【脚本会自动做什么】
  1  校验包内容，并确认这个包本身含新版代码（缺了就直接停下报警）
  2  先从【端口占用者的命令行】推断安装目录；
     推断不出就扫描磁盘，并用【线上首页正在引用的入口 JS】精确匹配安装目录
     （这样不会在多份副本里选错），同时打印旧进程的 PID / 路径 / 命令行
  3  备份现有 server\.env
  4  覆盖代码（server\src、server\data、server\scripts、web\dist 等），
     保留 uploads 与 node_modules；复制完立刻检查磁盘上是否已是新版
  5  处理 server\.env（已有则保留，缺失则用包内配置补上）
  6  检查依赖（node_modules 缺失时才 npm install），
     并执行 node src\init.js 幂等补建缺失的表 / 字段 / 索引
     （只新增不删改：products 有数据时会打印「已有数据，跳过导入」，不会覆盖线上商品）
  7  按【端口占用者 PID】精确结束旧服务，等端口真正释放后再启动
     （旧版就是这一步没生效，导致"部署成功但网站没变"）
  8  自检：新版路由 /api/admin/todos（旧代码 404 / 新代码 401）、
     前端入口 JS 指纹、开源项目接口、sitemap、商品图片
  9  给出明确结论：成功 / 未完全成功（并写进日志）

【可选参数】
  只扫描不改动:      powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -DryRun
  只核对代码是否干净: powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -VerifyOnly
                     （逐文件哈希比对安装目录与包内，列出缺失/不同/多余，不做任何改动；
                       全一致退出码 0，不一致退出码 1）
  指定安装目录:      powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -InstallDir "C:\你的路径"
  强制重装依赖:      powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -ForceNpmInstall

  提示：如果你已经知道安装目录，直接用 -InstallDir 最快，也最不容易出错。

【怀疑"代码没换干净"怎么办】
  1) 先核对：powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -VerifyOnly
     它会逐文件比对，告诉你到底哪些文件缺失或内容不同（安装目录多余的文件也会列出，但不删）。
  2) 再部署：powershell -ExecutionPolicy Bypass -File .\deploy.ps1
     部署是"全量覆盖"：server\src、server\data、server\scripts 里的代码文件全部按包内版本覆盖，
     web\dist 做镜像同步（包内已不存在的旧产物会被清掉），所以跑完就是包内的干净状态。
  3) 无需新建安装目录：商品图片（server\uploads）、server\.env、node_modules 都原地保留，不会丢。

【把网站注册成服务（防止注销/重启后掉线）】
  右键「注册服务.bat」-> 以管理员身份运行
  或：powershell -ExecutionPolicy Bypass -File .\install-service.ps1 -InstallDir "C:\你的\code-shop"
  卸载：schtasks /delete /tn "code-shop-server" /f

【包内配置的生效参数】
  端口 PORT=40621   （node 直接监听该端口对外服务，没有 Nginx 反代）
  数据库 62.234.122.127:6539 / code_shop
  站点地址 http://62.234.122.127:40621

【部署后请检查】
  1) 浏览器 Ctrl+F5 后，顶部导航有「开源项目」入口
  2) /opensource 显示 157 个项目，无空白卡片
  3) 商品列表页：搜索框只有一个、分页能点、商品卡片能进详情
  4) 页脚有「帮助中心 / 关于我们 / 服务条款 / 隐私政策」
  5) 商品图片正常显示（确认 uploads 未受影响）
  6) 后台首页出现待办区块，数据报表出现转化漏斗

【故障排查】
  - 运行需要管理员权限
  - 端口 40621 同一时间只能被一个进程占用
  - 如果脚本提示"端口仍被占用"，说明旧服务是被 Windows 服务或计划任务托管的：
    打开任务管理器 -> 详细信息，结束日志里给出的那个 PID，再重新运行
  - 日志文件在桌面：code-shop-deploy-日期-时间.log，出问题直接发这个文件

【注意事项】
  - 本包含有数据库口令与 JWT 密钥的明文配置，请勿外传
  - 脚本不会改数据库、不删 uploads、不删用户文件、不动 git 历史
